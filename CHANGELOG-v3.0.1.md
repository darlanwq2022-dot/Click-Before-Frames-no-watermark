# v3.0.1 — Native physics clock and wave reliability

- Removed the custom 240-TPS accumulator that wrapped `GJBaseGameLayer::update` and overrode `getModifiedDelta`. The game now owns its full native 2.2 physics loop; the mod's update hook is a pass-through observer only.
- Render FPS and physics steps per rendered frame are recorded separately in diagnostic exports.
- Prediction continues to use the actual player physics-step delta and the 240-Hz reference tick conversion; render FPS is not used to scale prediction ticks or CPU budget.
- Default wave lookahead raised to 240 ticks (1 second); prediction budget raised to 16 ms; no-hitch slices increased to 1 ms; resume limit remains 1024. Wave robustness now uses a quarter-tick position perturbation and avoids repeating the generic half-tick validation after its own checks, preserving more narrow-but-valid wave windows while retaining the adjacent-delay safety margin.
- One-time settings migration disables Low Latency / Performance Mode / auto budget, enables robust saves / wave safety margin / CBF sync, and raises old short wave horizons and tiny budgets.

## Important limitation

The attached user diagnostic was generated by v2.99.7, not v3.0.0 or v3.0.1. It showed a 4 ms configured budget, a 65-tick wave horizon and an `UNBUFFERED` result after the search had only reached +37 ticks of a 128-tick delay window. Those settings limited wave coverage. The updated defaults address those limits, but cannot guarantee a safe timing in every impossible gap or fix input latency that occurs before the mod receives the click.

This source was statically checked but not compiled against Geode SDK in this environment.
